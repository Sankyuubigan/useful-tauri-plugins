Модели ниже получены реальным запросом GET /models к провайдеру. Они и есть список, который видят IDE: пустой список означает, что провайдер не будет использоваться в чате.
Комбо-связка — именованная цепочка моделей с fallback: запрос идёт первому участнику, при его отказе — следующему. В чате связка выбирается одним именем. Порядок участников = приоритет.
Релей — воркер на Vercel или Cloudflare Workers. Он нужен, когда провайдер недоступен из вашей сети (региональная блокировка или фильтрация трафика): запросы выходят с территории платформы релея.

Мои релеи

Каждый провайдер выбирает свой релей в своей карточке на вкладке «Провайдеры»; новые провайдеры наследуют релей по умолчанию (кнопка «Назначить по умолчанию»). Секрет RELAY_TOKEN общий для всех релеев.

Развернуть автоматически

Vercel: Access Token (vercel.com/account/tokens). Cloudflare: API-токен с правом «Workers Scripts: Edit» (dash.cloudflare.com → My Profile → API Tokens). Шлюз сам загрузит воркер, поставит секрет RELAY_TOKEN и подставит URL.

Развернуть вручную

Ручной путь ниже — про Vercel (для Cloudflare проще авто-деплой выше). Надёжный, если авто-деплой недоступен. Скопируйте исходник воркера, создайте на Vercel Edge-проект, задайте переменные окружения RELAY_TOKEN (обязательно — нажмите «Показать секрет», чтобы скопировать его здесь) и, по желанию, ALLOWED_HOSTS (список хостов через запятую), затем вставьте выданный адрес ниже.
