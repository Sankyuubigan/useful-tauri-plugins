## Достаточность данных для чинения

- **Сообщения**: достаточны — типичный отчёт содержит тип, конкретную причину и
  контекст прямо в тексте (пример LoRA: путь + список доступных). ✔
- **Версия/ОС/сессия**: отсутствовали (`appVersion/osName/sessionId == ""` в
  error-detail) — GAP закрыт в `src/error_reporting/aptabase.rs` (`error_body`:
  appVersion/osName/osVersion/sdkVersion/platform/sessionId, усечение до лимитов
  ErrorBody.cs, 3 unit-теста). Эффект — с релиза нового бинаря. ⏳
- **Breadcrumbs**: в облако не доходят — сервер их отбрасывает (нет в ErrorBody.cs).
  Хроника — только в локальном `king_orch.log` юзера. Известное ограничение. ✖
- **Шум**: один инцидент порождает сотни записей (tarot-шторм: 1175 из ~1600
  ошибок месяца — один файл). Дедупликации на отправке нет; для анализа
  пользоваться `error-types`, а не сырым списком. Возможное будущее улучшение
  (вне этой задачи): rate-limit одинаковых errorType в плагине.
