# cloud-routers-gateway

Локальный LLM-шлюз с OpenAI-совместимым API. Обслуживает внешние IDE
(Cursor, Cline, Roo Code, Aider) и существует как **отдельный процесс**,
переживающий закрытие приложения-хоста.

## Почему отдельный процесс

Шлюз держит API-ключи облачных провайдеров и отвечает на запросы IDE по
`http://127.0.0.1:<порт>`. Если бы он жил внутри Tauri-приложения, закрытие
окна хоста обрывало бы инференс — а пользователь держит открытым именно IDE,
не хост. Поэтому процесс запускается **отсоединённым**
(`DETACHED_PROCESS` + `CREATE_NO_WINDOW` + `CREATE_NEW_PROCESS_GROUP`) и
продолжает работать после выхода из приложения.

## Запуск

```
cloud-routers-gateway --data-dir <каталог> [--port <порт>]
```

`--port` перекрывает значение из конфига и **не сохраняется**: конфиг остаётся
источником правды. Плагин передаёт порт явно, чтобы поднять шлюз на свободном
порту, не правя файл.

## Раскладка в каталоге данных

```
<data_dir>/
  gateway.json          провайдеры, ключи, модели, релей, порт
  presets_cache.json    кэш каталога провайдеров
  server.json           pid / порт / версия живого процесса
  gateway.log           stdout + stderr процесса
```

Записи атомарные (`ko-json-store::write_atomic`): читатель никогда не увидит
обрезанный JSON.

## API

| Маршрут | Кто ходит | Назначение |
|---|---|---|
| `GET /health` | плагин, человек | проверка живости |
| `GET /v1/models` | IDE | список комбо, формат OpenAI |
| `POST /v1/chat/completions` | IDE | прокси инференса (со стримингом) |
| `POST /chat/completions` | IDE | тот же путь без `/v1` |
| `GET /api/combos` | хост | список комбо в формате плагина |
| `GET /dashboard` | человек, iframe хоста | настройки |
| `/api/**` | дашборд | управление, журнал |

Модели и провайдеры **не захардкожены**: список получается реальным
`GET {base_url}/models` и хранится в конфиге. Пресеты провайдеров (имя,
`base_url`) лежат в `cloud-routers-gateway/assets/provider-presets.json` и
обновляются по сети — см. «Каталог провайдеров».

## Маршрутизация

Идентификатор комбо — строго `{provider_id}/{model_id}`, например
`groq/llama-3.3-70b-versatile`. Разделитель — **первый** `/`: идентификаторы
моделей реальных провайдеров сами содержат слэш (`meta-llama/Llama-3.3-70B`),
а id провайдера не содержит никогда (проверяется при сохранении конфига).

Запрос уходит на апстрим с подставленным настоящим `model`; всё остальное тело
(`tools`, `tool_choice`, `response_format`, любые будущие поля) сохраняется
как есть. Мы не переводим протоколы между вендорами — меняется только
routing-заголовок.

### Ротация ключей и лазейный фейловер

Несколько ключей на провайдера, выбор round-robin. Отказы делятся на две
категории:

| Отказ | Реакция |
|---|---|
| `401` / `403` | ключ **выключается на диске** — он не станет валидным сам |
| `429` | пауза из `Retry-After`, иначе 60 с |
| `5xx`, обрыв | пауза 15 с |
| прочие `4xx` | **не повторяем** — виноват запрос, а не ключ |

Повтор возможен **только до первого отправленного байта**. Как только ответ
принят и байты пошли в IDE, ретрая больше нет: иначе клиент получил бы два
ответа, склеенных в один. Это структурное свойство кода, а не проверка.

Если все живые ключи оказались в паузе, паузы сбрасываются один раз — иначе
шлюз деградировал бы в вечный `503`. Ключи, выключенные на диске, при этом не
оживают: они выключены осознанно.

### Стриминг

SSE-передаётся чанками через `Body::from_stream`, без буферизации: задержка
между токенами определяется только сетью. Общего таймаута запроса у HTTP-клиента
**нет** — `Client::timeout` ограничивает всю длительность, включая чтение тела,
и убил бы поток на первой длинной генерации. Вместо него таймаут соединения
(10 с) и таймаут между чтениями (180 с).

## Каталог провайдеров

Три уровня, по убыванию приоритета:

1. **Сетевой sync** — JSON по URL из `presets_sync_url`. Кнопка «Обновить
   каталог провайдеров» в дашборде.
2. **Кэш** `<data_dir>/presets_cache.json` — переживает рестарт и офлайн.
3. **Встроенный bundle** — `cloud-routers-core/assets/default_providers.json`
   через `include_str!`. Гарантирует рабочий список при первом запуске без сети.

Формат версионируется полем `version`; поддерживается диапазон `1..=1`. Версия
растёт **только** при несовместимом изменении полей — новые провайдеры и новые
`base_url` являются данными и апдейта софта не требуют.

Список моделей провайдера при этом **не** берётся из каталога: он означает
«апстрим это отдал на реальный `GET /models`». Пока опрос не выполнен,
провайдер не маршрутизируется.

## Релей (Vercel Edge)

Нужен, когда провайдер недоступен из сети пользователя. Запрос уходит через
Edge-функцию: `assets/relay-worker.js`, ставится на Vercel как
`api/gateway/[...path].js`.

Шлюз передаёт **абсолютный** URL цели в `x-target-url`, а не пару
«хост + путь»: склейка host и pathname даёт у провайдеров, чей `base_url`
уже заканчивается на `/v1`, двойной `/v1` и `404`.

Воркер требует `x-relay-token`, совпадающий с переменной окружения
`RELAY_TOKEN`. Без этого развёрнутый воркер был бы публичным прокси «куда
угодно» для всех, кто узнает URL. Если `RELAY_TOKEN` не задан, воркер отвечает
`503` и ничего не проксирует (fail-closed).

`ALLOWED_HOSTS` (необязательно) ограничивает список целевых хостов.

## Самоперезапуск

Порт и адрес bind читаются только при старте, поэтому смена порта в UI требует
перезапуска. Шлюз умеет перезапустить себя: новый экземпляр стартует первым и
терпеливо ждёт свободного порта, пока старый его держит; старый, убедившись,
что порт освобождён, завершается.

## Тесты

```
test-plugin.bat cloud-routers-core      # доменный слой
test-plugin.bat cloud-routers-gateway --bins
```

Интеграционные тесты поднимают мок-апстрима на `127.0.0.1` тем же `axum` и
проверяют то, что нельзя поймать тестом чистой функции: прозрачный ретрай по
ключу, деактивацию после `401`, побайтовую передачу SSE (первый чанк приходит
до конца ответа), отсутствие общего таймаута.
