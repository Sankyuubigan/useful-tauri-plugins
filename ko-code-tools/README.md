# ko-code-tools

**Ядро кодо-тулов агента (SSOT).** Реализация файловых, поисковых и shell-тулов
живёт здесь ровно ОДИН раз — хост King Orch и CLI `agent-tools` пользуются
одним и тем же кодом.

| Кто | Как пользуется |
|-----|----------------|
| King Orch (`src-tauri/src/infra/tools/`) | тонкие адаптеры: `trait Tool` хоста поверх `CodeTool` ядра; политика записи — хостовая (`PermissionApprover`, `WriteOutside`) |
| `agent-tools` (`code` / `code mcp`) | прямой вызов ядра: CLI `agent-tools code call <тул> --args '{...}'` и MCP-режим |

## Что внутри

| Модуль | Что делает |
|--------|------------|
| `contract.rs` | контракт: трейт `CodeTool` (имя/описание/schema/is_readonly/execute), контекст `ToolCtx`, ошибки `ToolError`, хук записи `WriteAuthorizer`, хук проверки качества `LintGate`, реестр `all_code_tools()` |
| `fs.rs` | фасад файловых тулов (имена тулов прежние): `fs/fs_read.rs` — `read_file`, `read_many_files` (гарды: устройства Windows, бинарные расширения, NUL-детект), `fs/fs_write.rs` — `write_file` (+ diff-сводка), `fs/fs_edit.rs` — `edit_file` (разбор `edits[]`, байтовые сплайсы, последовательное/нечёткое применение), `fs/fs_lint.rs` — baseline/проверка/откат + `LINT_CONTEXT_LINES` |
| `search.rs` | `grep` (regex, режимы content/files_with_matches/count, постраничный вывод) + общий обходчик `.gitignore`; `glob`, `list_directory` — в `search/listing.rs` |
| `shell.rs` | `bash` (таймаут, запрет git-мутаций и разрушительных команд), `run_tests` (белый список команд) |
| `fuzzy.rs` | третья попытка `edit_file`: нечёткое совпадение по нормализованным отступам/пробелам |
| `pruner.rs` | чистка вывода тестов: PASS-шум вон, имена упавших и стектрейсы — вон |

## Правила, которые ядро держит само

1. **Правило записи — через хук.** Ядро не решает, можно ли писать в файл:
   решение принимает хост (`WriteAuthorizer`). Дефолт для CLI —
   `AllowWithinRoot`: авто-запись только внутри корня, вне — честный запрет.
2. **Проверка качества — тоже хук.** `LintGate` (если подключён) снимает
   baseline ДО записи и сравнивает ПОСЛЕ: новая синтаксическая ошибка →
   запись откатывается, агент получает строки вокруг проблемы. Не подключён →
   проверки нет, и это объявлено в описании тула (а не выдаётся за «ошибок нет»).
3. **Никаких молчаливых дефолтов.** Любой отказ — `Result` с причиной;
   пустой ответ вместо ошибки недопустим.
4. **Пороги — константы кода**, а не аргументы тула: порог, который задаёт
   модель, она же и будет угадывать.
5. **Без C-компиляции** в графе зависимостей (правило репозитория плагина).
   Тяжёлые AST-парсеры (`syn`, `oxc`, `rustpython`) живут только в
   `agent-tools` — здесь их нет.

## Использование из хоста

```rust
use ko_code_tools::{CodeTool, ToolCtx, ToolError};

fn execute(tool: &dyn CodeTool, args: &serde_json::Value, ctx: &ToolCtx) -> Result<String, ToolError> {
    tool.execute(args, ctx)
}
```

Хост строит ядровой `ToolCtx` сам: `ToolCtx::new(workspace_root, &authorizer)`,
при необходимости `.with_lint_gate(&gate)`.

Фактическое состояние подключений: `agent-tools` подключает гейт (`SyntaxGate`
поверх синтакс-разбора rs/ts/js/tsx/jsx/py — см. README agent-tools, «Политика
записи»); хост King Orch в текущем релизе подключает `ToolCtx` БЕЗ гейта —
правки выполняются без автопроверки, и это объявлено в описании тулов (не
тишина).
