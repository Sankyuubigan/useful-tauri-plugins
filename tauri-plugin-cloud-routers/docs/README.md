# tauri-plugin-cloud-routers

Переиспользуемый плагин Tauri v2: **шлюз облачных LLM через несколько роутеров**
([9Router](https://github.com/decolua/9router), ExtremeRouter, OmniRoute).
Работает без системных зависимостей и терминала — плагин сам скачивает портативный
`node.exe` и standalone-бандл каждого роутера.

## Что делает

- **Установка «из коробки»**: `node.exe` (официальный zip с nodejs.org, LTS) +
  npm-тарболл роутера → распаковка в `APPDATA/cloud-routers/<id>/`. Пользователю не нужен
  установленный Node.js и админ-права.
- **Долгоживущий автозапуск по требованию**: сервер поднимается, когда хост
  реально использует роутер (например, выбрал комбо в чате), и продолжает работать
  в фоновом режиме после закрытия приложения, обслуживая и dev, и релизные сборки.
- **Комбо** из `/api/combos` — для дропдауна моделей чата.
- **OpenAI-совместимый чат** `/v1/chat/completions` со стримингом через
  Tauri-событие `cloud-routers-chunk`.
- **Веб-дашборд** в браузере по умолчанию.

## Поддерживаемые роутеры

| ID | Вид | Порт по умолчанию | Что запускается |
|----|-----|-------------------|-----------------|
| `9router` | node-бандл | 20128 | `node.exe` + `9router` из npm |
| `extremerouter` | node-бандл | 20129 | `node.exe` + extremerouter из npm |
| `omniroute` | node-бандл | 20130 | `node.exe` + omniroute из npm |
| `gateway` | наш бинарь | 20131 | `cloud-routers-gateway` (см. ниже) |

## Роутер `gateway` — собственный шлюз плагина

`gateway` отличается от остальных роутеров тем, что его код — **наш**: он не
скачивает npm-пакет и не запускает Node.js. Это отдельный бинарь
`cloud-routers-gateway` (крейт `cloud-routers-gateway` в этом же репозитории),
который плагин ставит кнопкой «Установить» и запускает отсоединённым процессом.

Что он даёт:

- **Ротация ключей** с лазейным фейловером: несколько ключей на провайдера,
  автоматический переход на следующий при `429`/`5xx`, постоянное отключение
  ключа после `401`.
- **Потоковый SSE без буферизации**: первый токен уходит в IDE с той же
  задержкой, что и при прямом подключении к провайдеру.
- **Каталог провайдеров по сети**: ни одна строка с `base_url` не зашита в код,
  список обновляется по кнопке и переживает офлайн (кэш + встроенный fallback).
- **Релей Vercel** для недоступных из региона провайдеров.
- **Собственный веб-интерфейс** (`/dashboard`), встроенный в панель плагина
  через `<iframe>` и открываемый кнопкой «Открыть Web UI».

Подробности — `cloud-routers-gateway/docs/README.md`.

### Настройки шлюза живут в его дашборде, а не в панели плагина

Формат конфигурации шлюза (провайдеры, ключи, ротация, релей, каталог
пресетов) не дублируется полями панели плагина. Причина: две правды об одном
объекте разъезжаются при первом же изменении. Панель показывает кнопки
управления и сам дашборд; всё состояние — в нём.

Единственное исключение — порт: он меняется в дашборде и требует перезапуска
процесса (кнопка «Перезапустить шлюз»).

### Жизненный цикл

В отличие от node-роутеров, шлюз на старте хоста **не убивается**, если уже
работает: он специально переживает закрытие приложения. Вместо этого при
обнаружении процесса прошлой версии выводится предупреждение.

Остановка шлюза сверяет исполняемый файл целевого pid с бинарём шлюза и **не
убивает ничего**, если не совпало: pid из `server.json` может принадлежать
другому процессу, и `taskkill` по нему ударил бы по работающему приложению.

### Ограничение по безопасности

Шлюз слушает **только loopback** и не требует авторизации — иначе каждый IDE
пришлось бы настраивать отдельно. CORS разрешён для любых источников, потому
что локальные IDE приходят со своим origin.

Следствие, о котором стоит знать: **любая страница в браузере** может обратиться
к `127.0.0.1:20131` и потратить ваши ключи провайдеров. Это осознанный размен:
требование «ноль настройки у IDE» против «только доверенные клиенты». Если для
вашей задачи приоритет обратный — включайте релей с обязательным секретом
(`RELAY_TOKEN`), он закрывает путь наружу.


## Rust-подключение

`src-tauri/Cargo.toml`:

```toml
tauri-plugin-cloud-routers = { path = "../../my-tauri-plugins/tauri-plugin-cloud-routers" }
```

`main.rs`:

```rust
tauri::Builder::default()
    .plugin(tauri_plugin_cloud_routers::init())
    // ...
    .run(tauri::generate_context!())
```

`capabilities/default.json` — добавить `"cloud-routers:default"`.

`tauri.conf.json` — `app.withGlobalTauri: true` (для vanilla-канала) и опционально:

```json
"plugins": { "cloud-routers": { "data_dir_name": "com.kingorch.app" } }
```

## Команды

Все команды принимают параметр `router: RouterId` (`"9router" | "extremerouter" | "omniroute"`).

| Команда | Назначение |
|---------|-----------|
| `get_status` | статус (installed/running/version/port/path), сервер не запускает |
| `install_or_update` | установка/обновление (портативный Node + роутер) |
| `ensure_started` | ленивый автозапуск по требованию |
| `stop` | остановка сервера |
| `set_router_dir` | смена папки установки + проверка наличия роутера по новому пути |
| `get_combos` | список LLM-комбо (лениво стартует сервер) |
| `open_dashboard` | открыть веб-дашборд |
| `chat_completion` | OpenAI-совместимый чат (SSE-стриминг) |

События: `cloud-routers-progress` (`{router, stage, done, total, text}`) — установка;
`cloud-routers-chunk` (`{router, text, author, kind}`) — стриминг чата.

## Frontend (TS / Web Component)

```ts
import { getStatus, getCombos, chatCompletion, onChunk } from '@my-tauri-plugins/plugin-cloud-routers'
```

Или vanilla (без бандлера): глобал `window.__TAURI__['cloud-routers']` + тег
`<cloud-routers-panel>` (панель статуса в настройках). JS вшит Tauri из
`api-iife.js` (см. `PLUGIN_STANDARD.md` §5.4).

Панель `<cloud-routers-panel>` позволяет сменить папку установки кнопкой
«Изменить путь»: выбирается каталог, путь сохраняется в `cloud_routers.<id>.dir`,
работающий сервер останавливается, и статус пересчитывается под новую папку
(если в ней нет `node.exe`/серверного скрипта — высветится «Установить»).

## Хранение

- Установка (node-роутеры): `APPDATA/cloud-routers/<id>/` (`runtime/node.exe`,
  `dist/app/…`), переопределяется ключом `cloud_routers.<id>.dir`.
- Установка (`gateway`): `APPDATA/cloud-routers/gateway/cloud-routers-gateway.exe`.
  Для шлюза ключ `dir` указывает **папку с бинарником** без вложенной подпапки.
- Папка установки принадлежит плагину, а не приложению: путь одинаков из любого
  проекта, поэтому один процесс шлюза виден и управляется из каждого из них.
- Данные (БД, auth, runtime): `%APPDATA%/<id>`, общие для всех приложений и для
  dev/релизных сборок. Поддерживается автомиграция из legacy `%APPDATA%/9router`.
- Идентичность сервера: `server.json` (pid, port, version, data_dir) в каталоге
  данных. Поле `version` добавлено с появлением шлюза; записи без него читаются
  корректно.
- Журнал шлюза: `gateway.log` в каталоге данных (обрезается при каждом старте).
- Конфиг роутеров: `APPDATA/cloud-routers/app_config.json` — файл САМОГО
  плагина, общий для всех проектов (как у `llama-engine`). При первом чтении
  секция `cloud_routers` переносится из старого per-app `app_config.json` хоста.
- Конфиг шлюза (провайдеры, ключи, релей): `gateway.json` в его каталоге
  данных — отдельный файл, потому что формат другой и он меняется самой
  настройкой шлюза.
- Порты по умолчанию: `20128`, `20129`, `20130`, `20131` (шлюз); бинд только на
  `127.0.0.1`.

## Сборка JS-плагина

При правке `guest-js/*`:

```
npm install
npm run build         # -> dist-js/ (npm-канал)
npm run build:global  # -> api-iife.js (vanilla-канал)
```

Оба артефакта коммитятся. Хост пересобирается через свой `.bat`-обёртчик.
