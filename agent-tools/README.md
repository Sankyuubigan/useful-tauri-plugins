# agent-tools

CLI-набор инструментов для ИИ-агентов кодеров. Без GUI: агент вызывает тул сам
(с согласия пользователя) из своей оболочки — например через `bash`.

Это **не Tauri-плагин**: нет `links`, `build.rs`, permissions и npm-пакета. Крейт —
обычный workspace-member `my-tauri-plugins` с бинарником `agent-tools`. Единственный
общий с остальным репозиторием примитив — `ko-json-store` (атомарные записи JSON).

| Инструмент | Назначение |
|------------|------------|
| [`codemap`](#codemap--карта-репозитория) | карта проекта под бюджет токенов: AST → граф → сжатый текст; плюс разведка по одному файлу (`skeleton`, `body`) |
| [`code`](#code--ядро-кодо-тулов) | ядро кодо-тулов агента: чтение/запись/поиск/shell — тот же код, что у хостовых тулов King Orch (крейт `ko-code-tools`) |
| [`consult`](#consult--эскалация-к-умной-модели) | отчёт рабочего агента → умная модель через шлюз 9Router, с жёстким лимитом вызовов |
| [`websearch`](#websearch--мульти-движковый-поиск) | интернет-поиск через 11 keyless-движков: цепочка фолбэков, multi-query, кеш и статистика отказов |

## Сборка и запуск

```bash
cargo build -p agent-tools --release          # target\release\agent-tools.exe
cargo test  -p agent-tools                    # unit + сквозные тесты (оффлайн)
test-plugin.bat agent-tools                   # только unit-тесты крейта (--lib)
```

Положить бинарь в `PATH` — и инструмент доступен агенту в любом проекте.

## Коды возврата

Число важнее текста: агент принимает решение по коду, а не по сообщению.

| Код | Что произошло | Поведение |
|-----|---------------|-----------|
| `0` | ответ получен, счётчик увеличен на 1 | в stdout шапка расхода + чистый ответ модели |
| `1` | лимит вызовов исчерпан | запрос **не выполняется**, в stderr директива остановки |
| `2` | ошибка ввода: нет файла отчёта, он пуст, отчёт > 64 МиБ, неизвестный флаг | сеть не трогается |
| `3` | ошибка сети/API: шлюз недоступен, 4xx/5xx, нечитаемый ответ | вызов **возвращается** в лимит |
| `4` | внутренняя ошибка: состояние не читается/не пишется | лимит не тронут |

Коды выдаёт сам процесс (`std::process::exit`), поэтому в связке «агент → тул» их
видно без разбора вывода.

## consult — эскалация к умной модели

Рабочий агент зашёл в тупик: он дешёвый, но задачу не решает. Он пишет отчёт и
(с разрешения пользователя) вызывает `consult`. Тул отправляет отчёт умной модели
через локальный OpenAI-совместимый шлюз **9Router**, печатает её ответ и выходит.
Каждый вызов стоит денег, поэтому число вызовов жёстко ограничено, а при исчерпании
инструмент не отвечает моделью, а **останавливает агента** кодом `1`.

### Использование

```bash
agent-tools consult report.md                       # отчёт из файла
cat report.md | agent-tools consult                 # отчёт из stdin
agent-tools consult - < report.md                   # то же явным дефисом
agent-tools consult --model google-high-tier big.md # конкретная модель
```

Служебные команды (сеть не трогают, лимит не тратят):

```bash
agent-tools consult --status                # Использовано 2 из 5. Осталось: 3
agent-tools consult --set-limit 10          # новый лимит вызовов
agent-tools consult --reset                 # счётчик вызовов в 0
agent-tools consult --state-file sub/state.json --status   # отдельный счётчик
```

Служебные флаги имеют приоритет над файлом отчёта: `consult report.md --status`
покажет статус, а не потратит вызов.

### Переменные окружения

| Переменная | Дефолт | Перекрывается флагом |
|------------|--------|----------------------|
| `ROUTER_BASE_URL` | `http://localhost:20128/v1` | `--base-url` |
| `ROUTER_API_KEY` | `9router-key` | — |
| `SMART_MODEL_NAME` | `smart-expert` | `--model` |
| `AGENT_TOOLS_LOG` | `warn` (уровень лога в stderr) | — |

Базовый адрес можно дать как с `/v1`, так и без — `/v1/chat/completions`
подставляется сам. Таймаут запроса — 300 с (промпт на 250k токенов умная модель
считает долго).

> ⚠️ **`smart-expert` из ТЗ на локальном 9Router не существует.** В списке
> `/v1/models` такого combo нет, поэтому вызов с дефолтом закончится `HTTP 4xx`
> и кодом `3`. Варианты: передавать `--model <реальное combo>`, задать
> `SMART_MODEL_NAME`, либо переименовать нужное combo в дашборде 9Router в
> `smart-expert`. Список доступных combo всегда свежий тут:
> `curl -s http://localhost:20128/v1/models | jq -r '.data[].id'`
> Дешёвая проверка связи — `google-low-tier`, тяжёлые задачи — `google-high-tier`
> или `kiro-high-tier`.

### Состояние и лимит

Файл `.consult_state.json` в рабочей директории:

```json
{ "calls": 2, "limit": 5 }
```

- пишется атомарно через `ko-json-store` (tmp → `sync_all` → `rename` + sidecar-лок),
  рядом появляется `.consult_state.json.lock`;
- вызов резервируется **до** сетевого запроса, поэтому два параллельных агента
  не израсходуют одну и ту же единицу;
- при ошибке сети/API резерв возвращается — неудачная попытка не стоит лимита;
- файл с битым JSON — ошибка `4` (тихо обнулять счётчик нельзя: лимит и нужен
  там, где агент упирается). Починить: `--reset` или `--set-limit`;
- `--state-file PATH` — свой счётчик (например на задачу или на проект);
  недостающие каталоги создаются сами.

### Пример вывода

Успех (код `0`):

```text
[ОТВЕТ ЭКСПЕРТА | Использовано вызовов: 1/5, осталось: 4]

Замени unwrap() на оператор ? — тогда ошибка уйдёт вызывающему коду, ...
```

Исчерпан лимит (код `1`, stderr, запрос к шлюзу не выполняется):

```text
====================== КРИТИЧЕСКАЯ ОСТАНОВКА ======================
[LIMIT_EXCEEDED]: Лимит обращений к эксперту исчерпан (5/5)!
ДИРЕКТИВА ДЛЯ АГЕНТА:
Тебе СТРОГО ЗАПРЕЩЕНО предпринимать дальнейшие действия по задаче.
Ты зашел в тупик. Прекрати выполнение bash-команд и правок кода.
Немедленно напиши пользователю отчет о тупике и жди его решения.
===================================================================
```

### Протокол для агента (фрагмент `AGENTS.md`)

```text
## Эскалация: consult

Если задача не решается: собери отчёт (что делал, что получилось, точные ошибки,
пути к файлам) в `report.md` и спроси у пользователя разрешение на вызов:

    agent-tools consult report.md

Коды возврата:
  0 — ответ получен, следуй указаниям эксперта;
  1 — лимит исчерпан, СТОП: не выполняй больше команд и правок, отчитайся
      пользователю и жди его решения;
  2 — отчёт не принят (нет файла / пуст) — исправь и повтори;
  3 — шлюз недоступен или ответил ошибкой — сообщи пользователю, повторять
      вызов бессмысленно.

Никогда не обходи лимит самостоятельно (не редактируй .consult_state.json).
```

## codemap — карта репозитория

Агент начинает работу в чужом проекте. Прежде чем читать файлы наугад, он
разворачивает проект на диске, строит индекс и получает **сжатую карту под
бюджет токенов**: каталоги, а затем реальные строки кода вокруг самых важных
символов.

Заменяет ручное «прочитай 40 файлов» и Deno-инструмент `ast_treesitter.ts`
в King Orch.

### Команда, которую даётся агенту

```bash
# 1. Развернуть индекс один раз (~1 с на 361 файл, дальше — кеш).
agent-tools codemap index --path .

# 2. Карта под бюджет 2048 токенов (дефолт). Дальше — НЕ искать наугад.
agent-tools codemap map --path . --tokens 2048

# 3. Когда задача привязана к модулям — сфокусированная карта.
#    Фокусный файл поднимается наверх (ГЕЙТ 12).
agent-tools codemap map --path . --tokens 4096 \
    --file src-tauri/src/domain/orchestrator/mod.rs \
    --file src-tauri/src/domain/workflow_engine/nodes.rs

# 4. Точечно: кто зовёт символ / где он живёт.
agent-tools codemap callers  --path . build_system_prompt
agent-tools codemap search   --path . run_chat
agent-tools codemap skeleton --path . src/файл.rs
agent-tools codemap body     --path . src/файл.rs someSymbol

# 5. Разбор концентрации ранга — в stderr, stdout остаётся чистой картой.
agent-tools codemap map --path . --explain
```

**Шаги 2 и 3 взаимозаменяемы:** карта без фокуса отвечает на вопрос «что вообще
есть в проекте», карта с `--file` — «что нужно именно здесь». Если задача уже
известна, `--file` полезнее.

> `map` сам построит индекс, если его нет. Отдельный `index` нужен только чтобы
> контролировать момент пересборки или увидеть статистику разбора.

### Выбор команды по типу вопроса

Инструмент существует, чтобы вопрос о коде не превращался в перебор. На каждый
вопрос — один вызов:

| Вопрос | Команда |
|---|---|
| «где объявлена функция X, где она вообще есть» | `codemap search --path . X` |
| «кто вызывает X» | `codemap callers --path . X` |
| «что за проект, какие в нём модули» | `codemap map --path . --tokens 2048` |
| «покажи модуль X изнутри» | `codemap map ... --file <путь к X>` |
| «что внутри этого файла, но без тел» | `codemap skeleton --path . <файл>` |
| «покажи тело одного символа» | `codemap body --path . <файл> <символ>` |

Многократный `grep` по всему дереву там, где вопрос про символ, — это ровно то,
ради чего команда существует: она отвечает на тот же вопрос за один вызов.

Таблица выше отвечает «когда codemap»; раздел ниже — «когда ответ надо брать
не из codemap».

### Когда codemap НЕ нужен

Тул отвечает вопросом о **символах и связях** (карта, где объявлено, кто
вызывает). Три класса вопросов, для которых это не ответ, и их штатные средства:

| Класс вопроса | Почему не codemap | Чем брать |
|---|---|---|
| Сырые совпадения строк и контекстные окна (`-C`/`-A`/`-B`) — в любом дереве, включая своё | Тул отдаёт структуру (символы, связи), а не вывод grep | `rg`/grep |
| Значения в данных и конфигах: `Cargo.lock`, `package-lock.json`, манифесты, markdown-доки | Символов там нет; нужны конкретные строки и окружение | `rg`/grep/`read`; версии крейтов в сборке — `cargo tree -i <crate>` / `cargo metadata` |
| Агрегация пайплайном (`sort`/`uniq`/`count`/`head` поверх поиска) | Тул возвращает карту под бюджет токенов, а не grep-вывод для пайпа | bash-пайплайн на grep/rg |

Карта чужого дерева — в этот список не входит: она разрешена one-shot-режимом
ниже. Из «чужого» недоступны только сырые текстовые совпадения — это первая
строка таблицы, независимо от дерева.

### Карта чужого дерева (one-shot)

Индекс с кешем привязан к одному корню `--path` и хранится в нём же — для
крейта из cargo registry или соседнего репозитория хранить индекс по месту
нельзя. Для таких корней у `map` / `search` / `callers` есть флаг `--no-cache`:

```bash
# Карта крейта из registry одним вызовом, без единой записи на диск.
agent-tools codemap map --path "C:\Users\user\.cargo\registry\src\index.crates.io-…\tauri-plugin-updater-2.10.1" \
    --no-cache --tokens 1024
```

С флагом тул никогда не создаёт ничего на диске: полную сборку (scan + parse)
платит каждый вызов, индекс считается в памяти, карта идёт в stdout, каталог
`.codemap/` и правки `.git/info/exclude` чужого корня не появляются. `index`
с флагом несовместим по определению (операция существует ради кеша) — возвращает
код 2 с объяснением. Прогресс в stderr виден на уровне info (`AGENT_TOOLS_LOG=info`).

Цена честная: несколько сотен мс на крейт (`map` без кеша на своём проекте —
1,4 с до индексации, чужой крейт в разы меньше), против одного раунда модели —
не о чём. Для СВОЕГО проекта флаг не нужен: ежедневные `map`/`search` остаются
на дисковом индексе (0,24 с вместо 1,4 с).

### Свежесть индекса

Индекс сам сверяется с диском при каждом `map` / `search` / `callers`: обход
берёт только метаданные (`mtime` и размер) и перечитывает файл лишь тогда,
когда его дата разошлась с индексом. Поэтому удалённый файл сразу исчезает из
карты, а созданный — сразу появляется, без ручного `codemap index`.

Плата за это названа прямо: сверка стоит одного обхода метаданных. На проекте в
361 файл это ≈90 мс, ради чего карта перестала стоить 1.4 с.

### Что внутри карты

Три слоя, каждый отвечает на свой вопрос:

1. **Шапка** — сколько файлов, символов и токенов в проекте.
2. **Инвентарь `## 📁 Структура проекта`** — каталоги по архитектурному весу,
   с числом файлов, токенами и именами главных файлов; одной строкой в конце —
   какие каталоги инструмент сознательно не смотрел (артефакты сборки,
   `.gitignore`). Занимает ~12% бюджета.
3. **Блоки кода** — реальные строки исходника (две до и одна после строки
   определения, многоточие между разрывами) с номером строки.

### Свойства, на которые можно опираться

| Свойство | Значение |
|----------|----------|
| Широта | бюджет 2048 на king_orch_3 (360 файлов) покрывает **33 разных файла** |
| Потолок на файл | `min(15% бюджета, 250 токенов)`; на практике максимум 4.2% |
| Импорты | в карте **не** появляются определениями: `import { invoke }` — это ссылка |
| Поля класса | в карту **не** попадают: остаются заголовок класса и его методы |
| Кеш | индекс переиспользуется по `mtime`; `FORMAT_VERSION` инвалидирует его при смене правил разбора |
| Свежесть | индекс сам сверяется с диском; удалённый файл исчезает, новый появляется без `codemap index` |
| Хранилище | `<корень>/.codemap/`, идемпотентно дописывается в `.git/info/exclude` (`.gitignore` не трогается) |
| `.gitignore` | соблюдается строго; `node_modules` на 338k файлов в обход не заходит |
| Скорость | map ≈0.24 с; из них ≈0.09 с — сверка свежести; тёплый `index` ≈0.09 с |

### Как положить бинарь туда, где его зовут агенты

Постоянный путь — **`D:\Projects\my-tauri-plugins\bin\agent-tools.exe`**. Он
принадлежит репозиторию инструмента, а не King Orch, потому что пользоваться им
должны агенты в **любом** проекте, а не только внутри King Orch.

Обновляется одной командой из корня `my-tauri-plugins`:

```bat
scripts\build_binaries.cmd
```

Скрипт делает `cargo build --release -p agent-tools` и копирует результат в
`bin\`. Папка `bin\` в `.gitignore` — бинарь не коммитится.

> **Почему не `target\release\agent-tools.exe`:** там сборка и лежит, но
> `target\` удаляется командой `cargo clean`, и путь существует только пока идёт
> сборка. Путь к инструменту должны знать агенты и хосты — он обязан быть
> постоянным. Второй причиной две копии одного бинаря разъезжаются: `bin\` —
> единственное место, где он лежит.

Команда, которую даётся агенту (работает из корня любого проекта):

```bash
D:\Projects\my-tauri-plugins\bin\agent-tools.exe codemap map --path . --tokens 2048
```

> В MCP-режиме (`codemap mcp --path .`) корень проекта фиксируется флагом `--path`
> при запуске сервера, а не аргументом тула: сессия MCP работает с одним проектом.
> В режиме CLI `--path` можно передавать на каждый вызов.

### Проверочные скрипты

`agent-tools/scripts/` — переиспользуемый код проверки, а не результаты прогонов:

| Скрипт | Что делает |
|---|---|
| `gate_check.js` | `node gate_check.js <карта> <бюджет>` — проверяет карту по гейтам: ширина, потолок на файл, доля инвентаря, отсутствие импортов и полей класса вверху карты |
| `graph_probe.js` | `node graph_probe.js <index.json>` — разбирает индекс и печатает суммы входящих/исходящих рёбер: сразу видно, почему файл в карте не поднялся |

Прогоны и дампы сюда **не** кладутся: `test/` во всех каталогах репозитория
в `.gitignore` — это черновик по правилу §1.2, а не содержимое репозитория.

### Поддерживаемые языки

| Язык | Бэкенд | Что извлекается |
|------|---------|-----------------|
| Rust | `syn` | `fn`, `struct`, `enum`, `trait`, `type`, `const`, `static`, `mod`, методы; `use` → ссылки |
| TS / JS / TSX / JSX | `oxc_parser` + `oxc_semantic` | функции, классы, переменные уровня модуля, методы; разрешённые ссылки из таблицы символов |
| Python | `rustpython-parser` | `def`, `class`, вложенные функции; `import` → ссылки |
| всё остальное | плоский текст | доступно поиску, символов не даёт |

Си-компиляции нет во всём графе зависимостей: `syn`, `oxc_*` и `rustpython` его
не требуют.

### MCP-режим

```bash
agent-tools codemap mcp --path . --tokens 2048     # JSON-RPC 2.0 построчно через stdin/stdout
```

Инструменты: `codemap_index`, `codemap_map` (принимает `tokens` и `files` —
тот же фокус, что и `--file`), `codemap_search`, `codemap_callers`,
`codemap_get_skeleton` (скелет одного файла: импорты и сигнатуры с номерами
строк) и `codemap_get_body` (тело одного символа: от строки объявления до
начала следующего объявления; граница названа в ответе).

**Весь stdout принадлежит протоколу.** Весь лог — только в stderr; единственное
место, которое пишет в stdout, — функция `send` в `mcp.rs`.

### Диагностика

```bash
set AGENT_TOOLS_LOG=info    # весь лог в stderr (warn по умолчанию)
```

`--explain` печатает в stderr долю топ-5 файлов в сумме рангов: если один файл
забирает больше половины, граф схлопнулся и карта врёт. В stdout флаг ничего не
добавляет — это канал карты.

### Известные ограничения

- **Ранг по кросс-файловым ссылкам, а не по размеру.** В king_orch_3 фронтенд
  получает больше рёбер, чем Rust-слой, и `orchestrator/mod.rs` в карту на 2048
  токенов не попадает (в 32768 — попадает). Это свойство графа проекта: символы
  `orchestrator` никто не импортирует по имени.
- **Счётчиков файлов в сводке игнорируемого нет.** В `.gitignore`-каталогах
  king_orch_3 лежит 130k файлов (`test/`, `temp/`); считать их ради строки в
  карте означало бы второй полный обход. Сводка называет каталоги, но не
  притворяется точной.
- **Инвентарь показывает не все каталоги.** На 2048 токенах влезает ~6 каталогов
  из 63; остальные честно объявлены строкой `… ещё N каталогов`.

## code — ядро кодо-тулов

Инструмент `code` — доступ к **общему ядру кодо-тулов агента**. Реализация
живёт в крейте `ko-code-tools` (workspace-member этого же репозитория) и тем же
кодом пользуется хост King Orch: реализация одна на всех, а не копия в двух
репозиториях.

Тулы: `read_file`, `read_many_files`, `write_file`, `edit_file`, `grep`, `glob`,
`list_directory`, `bash`, `run_tests`.

### Использование

```bash
agent-tools code call read_file --root . --args '{"path":"src/main.rs"}'
agent-tools code call grep    --root . --args '{"pattern":"fn main","path":"src"}'
agent-tools code call bash    --root . --args '{"command":"cargo test"}'
```

`--root` — корень проекта (по умолчанию текущий каталог), `--args` — JSON
аргументов тула (по умолчанию `{}`). Имя тула — позиционный аргумент; список
доступен через `agent-tools code mcp` → `tools/list`.

### MCP-режим

```bash
agent-tools code mcp --root .     # JSON-RPC 2.0 построчно через stdin/stdout
```

`tools/list` отдаёт те же девять тулов со схемами из ядра; `tools/call` —
обычный вызов. Ошибка (нет файла, запрет записи) приходит как `isError` с
текстом причины.

### Политика записи

- CLI: авто-запись только внутри корня (`--root`); вне — честный отказ с
  причиной и кодом 4. Молчаливой записи нет;
- линт-гейт («новая синтаксическая ошибка → откат правки») в CLI **не
  выполняется**: сервера проверки здесь нет, и это объявлено в описании тула.
  В хосте King Orch гейт подключён к `rust-analyzer`, и правка, ломающая код,
  откатывается с показом строк вокруг ошибки.

### Что умеет ядро сверх «простого варианта»

- `edit_file` ищет фрагмент тремя попытками: точное совпадение → снятие
  префиксов номеров строк → нечёткое совпадение (нормализация отступов и
  пробелов; кандидат должен быть **ровно один**, иначе — отказ с перечнем
  кандидатов, а не правка не того места);
- `run_tests` выкидывает PASS-шум из вывода тестов и режет огромный блок
  упавшего теста **посередине** (голова + хвост): стектрейс в конце остаётся.

## websearch — мульти-движковый поиск

Прямой порт Deno-тулa `src-tauri/mcp_servers/web_search.ts` из King Orch
(диф-аудит 1-в-1, см. `king_orch_3/tasks/18.10.26 Порт поисковых тулов в
agent-tools.md`). 11 keyless-движков: `duckduckgo`, `wiby`, `marginalia`,
`brave`, `startpage`, `sogou`, `baidu`, `bing`, `juejin`, `csdn`, `exa`,
с антибот-эвристиками (DDG «anomaly», PoW-челлендж startpage, капчи).

### Использование

```bash
agent-tools websearch "rust tokio mpsc channel"           # цепочка фолбэков (дефолт)
agent-tools websearch "rust tokio" --limit 5              # до 5 результатов (3..20)
agent-tools websearch --queries "tokio,axum"              # multi-query, до 5 запросов
agent-tools websearch --engines "duckduckgo,brave" ...    # свой список (fan-out)
agent-tools websearch --stats                             # сводка статистики движков
agent-tools websearch mcp                                 # MCP: JSON-RPC 2.0 stdin/stdout
```

Агент вызывает `bash`-ом с `timeout = 120000`: живой поиск иногда идёт
20–60 с (цепочка движков с дедлайнами). Кеш результатов — 30 минут
(`search_cache.json` рядом с бинарем, путь умеет переопределяться env
`KING_ORCH_BINS_DIR`).

### Коды возврата

| Код | Что произошло |
|-----|---------------|
| `0` | есть результат (в stdout, формат: `[N] Название`, `Ссылка:`, `Описание:`) |
| `2` | ошибка ввода (пустой/слишком много запросов, неизвестный флаг) |
| `3` | все движки упали или вернули пусто — текст причины в stdout; ретрать того же запроса подряд бессмыслен |

### MCP-контракт

`agent-tools websearch mcp` — тот же протокол, что у Deno-сервера
`web_search.ts`: `initialize` → `tools/list` → `tools/call` c
`{"name":"WebSearch","arguments":{"query":"...","limit":N}}`. Ответы
построчно, весь лог — в stderr, stdout принадлежит протоколу.

## Тесты

```bash
cargo test -p agent-tools --lib        # unit: состояние, CLI, URL, контракты
cargo test -p agent-tools --test cli_e2e   # сквозные: реальный бинарь + стаб-шлюз
```

Сквозные тесты поднимают стаб на `127.0.0.1:0` и проверяют коды возврата, потоки,
состояние и сам HTTP-запрос (путь `/v1/chat/completions`, заголовок `Authorization`,
имя модели, системный промпт). Отдельно проверяется, что при исчерпанном лимите и
при ошибке ввода **ни одного запроса к шлюзу не уходит**. Модель в тестах —
`google-low-tier` (реальное combo локального 9Router).

Живой прогон настоящего шлюза помечен `#[ignore]` (нужен запущенный 9Router, он
тратит лимит и токены):

```bash
cargo test -p agent-tools --test cli_e2e -- --ignored --nocapture
```
