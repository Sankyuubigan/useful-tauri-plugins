# agent-tools

CLI-набор инструментов для ИИ-агентов кодеров. Без GUI: агент вызывает тул сам
(с согласия пользователя) из своей оболочки — например через `bash`.

Это **не Tauri-плагин**: нет `links`, `build.rs`, permissions и npm-пакета. Крейт —
обычный workspace-member `my-tauri-plugins` с бинарником `agent-tools`. Единственный
общий с остальным репозиторием примитив — `ko-json-store` (атомарные записи JSON).

| Инструмент | Назначение |
|------------|------------|
| [`consult`](#consult--эскалация-к-умной-модели) | отчёт рабочего агента → умная модель через шлюз 9Router, с жёстким лимитом вызовов |

## Сборка и запуск

```bash
cargo build -p agent-tools --release          # target\release\agent-tools.exe
cargo test  -p agent-tools                    # unit + сквозные тесты (оффлайн)
test-plugin.bat agent-tools                   # только unit-тесты крейта (--lib)
```

Положить бинарь в `PATH` — и инструмент доступен агенту в любом проекте.

## Коды возврата

Число важнее текста: агент принимает решение по коду, а не по сообщению.

| Код | Что произошло | Поведение |
|-----|---------------|-----------|
| `0` | ответ получен, счётчик увеличен на 1 | в stdout шапка расхода + чистый ответ модели |
| `1` | лимит вызовов исчерпан | запрос **не выполняется**, в stderr директива остановки |
| `2` | ошибка ввода: нет файла отчёта, он пуст, отчёт > 64 МиБ, неизвестный флаг | сеть не трогается |
| `3` | ошибка сети/API: шлюз недоступен, 4xx/5xx, нечитаемый ответ | вызов **возвращается** в лимит |
| `4` | внутренняя ошибка: состояние не читается/не пишется | лимит не тронут |

Коды выдаёт сам процесс (`std::process::exit`), поэтому в связке «агент → тул» их
видно без разбора вывода.

## consult — эскалация к умной модели

Рабочий агент зашёл в тупик: он дешёвый, но задачу не решает. Он пишет отчёт и
(с разрешения пользователя) вызывает `consult`. Тул отправляет отчёт умной модели
через локальный OpenAI-совместимый шлюз **9Router**, печатает её ответ и выходит.
Каждый вызов стоит денег, поэтому число вызовов жёстко ограничено, а при исчерпании
инструмент не отвечает моделью, а **останавливает агента** кодом `1`.

### Использование

```bash
agent-tools consult report.md                       # отчёт из файла
cat report.md | agent-tools consult                 # отчёт из stdin
agent-tools consult - < report.md                   # то же явным дефисом
agent-tools consult --model google-high-tier big.md # конкретная модель
```

Служебные команды (сеть не трогают, лимит не тратят):

```bash
agent-tools consult --status                # Использовано 2 из 5. Осталось: 3
agent-tools consult --set-limit 10          # новый лимит вызовов
agent-tools consult --reset                 # счётчик вызовов в 0
agent-tools consult --state-file sub/state.json --status   # отдельный счётчик
```

Служебные флаги имеют приоритет над файлом отчёта: `consult report.md --status`
покажет статус, а не потратит вызов.

### Переменные окружения

| Переменная | Дефолт | Перекрывается флагом |
|------------|--------|----------------------|
| `ROUTER_BASE_URL` | `http://localhost:20128/v1` | `--base-url` |
| `ROUTER_API_KEY` | `9router-key` | — |
| `SMART_MODEL_NAME` | `smart-expert` | `--model` |
| `AGENT_TOOLS_LOG` | `warn` (уровень лога в stderr) | — |

Базовый адрес можно дать как с `/v1`, так и без — `/v1/chat/completions`
подставляется сам. Таймаут запроса — 300 с (промпт на 250k токенов умная модель
считает долго).

> ⚠️ **`smart-expert` из ТЗ на локальном 9Router не существует.** В списке
> `/v1/models` такого combo нет, поэтому вызов с дефолтом закончится `HTTP 4xx`
> и кодом `3`. Варианты: передавать `--model <реальное combo>`, задать
> `SMART_MODEL_NAME`, либо переименовать нужное combo в дашборде 9Router в
> `smart-expert`. Список доступных combo всегда свежий тут:
> `curl -s http://localhost:20128/v1/models | jq -r '.data[].id'`
> Дешёвая проверка связи — `google-low-tier`, тяжёлые задачи — `google-high-tier`
> или `kiro-high-tier`.

### Состояние и лимит

Файл `.consult_state.json` в рабочей директории:

```json
{ "calls": 2, "limit": 5 }
```

- пишется атомарно через `ko-json-store` (tmp → `sync_all` → `rename` + sidecar-лок),
  рядом появляется `.consult_state.json.lock`;
- вызов резервируется **до** сетевого запроса, поэтому два параллельных агента
  не израсходуют одну и ту же единицу;
- при ошибке сети/API резерв возвращается — неудачная попытка не стоит лимита;
- файл с битым JSON — ошибка `4` (тихо обнулять счётчик нельзя: лимит и нужен
  там, где агент упирается). Починить: `--reset` или `--set-limit`;
- `--state-file PATH` — свой счётчик (например на задачу или на проект);
  недостающие каталоги создаются сами.

### Пример вывода

Успех (код `0`):

```text
[ОТВЕТ ЭКСПЕРТА | Использовано вызовов: 1/5, осталось: 4]

Замени unwrap() на оператор ? — тогда ошибка уйдёт вызывающему коду, ...
```

Исчерпан лимит (код `1`, stderr, запрос к шлюзу не выполняется):

```text
====================== КРИТИЧЕСКАЯ ОСТАНОВКА ======================
[LIMIT_EXCEEDED]: Лимит обращений к эксперту исчерпан (5/5)!
ДИРЕКТИВА ДЛЯ АГЕНТА:
Тебе СТРОГО ЗАПРЕЩЕНО предпринимать дальнейшие действия по задаче.
Ты зашел в тупик. Прекрати выполнение bash-команд и правок кода.
Немедленно напиши пользователю отчет о тупике и жди его решения.
===================================================================
```

### Протокол для агента (фрагмент `AGENTS.md`)

```text
## Эскалация: consult

Если задача не решается: собери отчёт (что делал, что получилось, точные ошибки,
пути к файлам) в `report.md` и спроси у пользователя разрешение на вызов:

    agent-tools consult report.md

Коды возврата:
  0 — ответ получен, следуй указаниям эксперта;
  1 — лимит исчерпан, СТОП: не выполняй больше команд и правок, отчитайся
      пользователю и жди его решения;
  2 — отчёт не принят (нет файла / пуст) — исправь и повтори;
  3 — шлюз недоступен или ответил ошибкой — сообщи пользователю, повторять
      вызов бессмысленно.

Никогда не обходи лимит самостоятельно (не редактируй .consult_state.json).
```

## Архитектура

```text
src/main.rs                  вход: выбор инструмента, код возврата процесса
src/exit.rs                  контракт «тул ↔ агент»: коды 0/1/2/3/4
src/logging.rs               минимальный log::Log → stderr
src/tools/mod.rs             реестр инструментов (Tool, ALL)
src/tools/consult/cli.rs     аргументы сабкоманды + разбор намерения
src/tools/consult/state.rs   состояние и лимиты (reserve/refund/is_exhausted)
src/tools/consult/client.rs  HTTP к OpenAI-совместимому API шлюза
src/tools/consult/mod.rs     сценарий выполнения, директива остановки, чтение отчёта
```

Добавление инструмента: создать `src/tools/<name>/`, добавить вариант в
`Tool` и его разбор в `Tool::from_args`, вписать в `ALL`. `main.rs` не меняется.

## Тесты

```bash
cargo test -p agent-tools --lib        # unit: состояние, CLI, URL, контракты
cargo test -p agent-tools --test cli_e2e   # сквозные: реальный бинарь + стаб-шлюз
```

Сквозные тесты поднимают стаб на `127.0.0.1:0` и проверяют коды возврата, потоки,
состояние и сам HTTP-запрос (путь `/v1/chat/completions`, заголовок `Authorization`,
имя модели, системный промпт). Отдельно проверяется, что при исчерпанном лимите и
при ошибке ввода **ни одного запроса к шлюзу не уходит**. Модель в тестах —
`google-low-tier` (реальное combo локального 9Router).

Живой прогон настоящего шлюза помечен `#[ignore]` (нужен запущенный 9Router, он
тратит лимит и токены):

```bash
cargo test -p agent-tools --test cli_e2e -- --ignored --nocapture
```
